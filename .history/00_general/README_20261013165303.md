# AnswerALS data preparation and nf-core support

This directory contains scripts and working notes used to prepare AnswerALS participant metadata and omics file manifests for nf-core pipeline runs and downstream PhD analyses. The workflow links participant-level metadata to released files, selects eligible samples, assigns analysis batches, and provides utilities for generating RNA-seq samplesheets and reviewing Nextflow resource use.

The scripts support preparation and organization of data. They do not download or redistribute AnswerALS data, and they do not replace the pipeline-specific validation required before running nf-core workflows.

## Workflow overview

The numbered directories indicate the broad order of work:

1. **Filter and match participants** — select participants with the required omics availability, exclude listed proteomics batch-effect samples, link metadata to sample-mapping records, and join participants to released-file paths.
2. **Create sample batches** — separate BDC and BTC records and create or validate artificial batch assignments. The batch scripts were developed iteratively; check each script’s inputs, parameters, and outputs before choosing one for a new analysis.
3. **Prepare pipeline inputs** — create samplesheets from paired FASTQ files and organize downloaded file layouts when needed.
4. **Review resource use** — summarize Nextflow execution traces and generate suggested process resource overrides.
5. **Look up Nextflow syntax** — build and retain a searchable Markdown reference from the official Nextflow documentation.

## Data preparation logic

The documented participant-matching workflow uses AnswerALS data-portal metadata, released-file manifests, the sample-mapping file, and a list of proteomics samples identified as having strong batch effects. The documented selection retains participants with genomics, transcriptomics, and proteomics availability, removes the listed proteomics batch-effect participants, maps remaining participants to sample records, and excludes epigenomics where it is outside the analysis scope. The workflow then separates BTC and BDC records and creates joined metadata and file-path tables.

The included notes describe a cohort of 347 participants for one historical data snapshot. This is not a guaranteed count for later portal releases: source tables, inclusion rules, and file availability may change. Treat the output tables and run-specific manifests as the authority for any particular analysis.

The batch scripts support balancing and coordinating transcriptomics and proteomics work while retaining diagnosis and sex representation and accounting for technical batches. BTC records are treated as technical controls in the documented strategy and are handled separately from biological participant samples. Review the batch notes and validation outputs to understand the exact logic used for a given set of results.

## Running selected utilities

Use Python 3, R, and the packages imported by the selected script. Commands below are examples; run them from the relevant directory or provide explicit paths. Paths in several older R scripts are relative to the working directory.

### Filter and match participant metadata

The R scripts in `01_filtering_matching_patients/code/` are staged by filename, including participant filtering, metadata/sample mapping, BDC/BTC splitting, and the full metadata/file merge. They expect source CSV files such as the AnswerALS data-portal table, released-file manifest, sample-mapping file, and proteomics batch-effect list. Those inputs must be obtained through the authorized AnswerALS access route and placed where the scripts expect them, or the scripts must be updated with the appropriate paths.

The historical workflow and intended inputs/outputs are described in `01_filtering_matching_patients/AALS_sample_filtering_matching_june2025.md`. Inspect the selected script before execution; the notes include historical code and data counts that may not reflect a current portal release.

### Assign and validate batches

Batch code and example data are under `02_sample_batches/`. For example, some Python scripts use pandas, NumPy, and scikit-learn; R scripts use tidyverse packages. Several scripts set input/output filenames and parameters near the top of the file rather than accepting command-line arguments. Confirm that the input files correspond to the intended cohort and that the generated transcriptomics and proteomics assignments remain aligned before pipeline execution or integration analyses.

### Create an RNA-seq samplesheet

`03_make_samplesheets/code/create_rnasplice_samplesheet.py` searches recursively for paired `*_1.fastq.gz`/`*_2.fastq.gz` or `*_R1.fastq.gz`/`*_R2.fastq.gz` files and writes a CSV with `sample`, `fastq_1`, `fastq_2`, `strandedness`, and `condition` columns.

```bash
python 03_make_samplesheets/code/create_rnasplice_samplesheet.py /path/to/fastq_directory samplesheet.csv
```

The script currently sets strandedness to `forward` and infers condition from `CASE-` or `CTRL-` in a file path. Confirm that these values and the resulting sample identifiers match the requirements of the specific nf-core pipeline and the experimental design. Review the output for unmatched or incorrectly paired reads before launching a workflow.

`03_make_samplesheets/code/unpack_dir.py` moves files from nested subdirectories into a supplied parent directory and removes empty subdirectories. This changes the input directory structure; use it only when that flattening is appropriate for the downloaded data layout.

### Analyze Nextflow execution traces

`04_resource_optimization/01_optimize_resources.py` searches recursively for `execution_trace_*` files in a directory and writes summaries and a suggested Nextflow resource configuration. For example:

```bash
python 04_resource_optimization/01_optimize_resources.py --input-dir /path/to/nf-results --output-prefix rnasplice_
```

Options include `--time-headroom`, `--time-quantile`, and `--min-time-minutes`; run `python 04_resource_optimization/01_optimize_resources.py --help` for defaults and full details. Recommendations are based on observed runs and should be reviewed against the pipeline, scheduler limits, sample scale, and failed-task history before use.

### Refresh the Nextflow syntax reference

`00_nf_syntax/extract_nf_syntax_07042026.py` fetches documentation pages from nextflow.io and builds the Markdown reference files. It requires network access and Python packages `requests` and `beautifulsoup4`. Its output reflects the documentation available at the time it is run and may differ from the checked-in snapshot.

## Reproducibility and data stewardship

- AnswerALS participant metadata and omics files may be controlled-access or governed by data-use terms. Obtain them from the official portal under the applicable approvals. Do not commit participant-level data, sample identifiers, file paths that reveal restricted information, credentials, or access codes to a public repository.
- Before publishing, review all tracked files and generated outputs for restricted or identifiable information. Keep sensitive input data and derived participant-level tables outside the public repository unless their release is explicitly permitted.
- Record the source release, retrieval date, filtering criteria, script version, and relevant parameters for each analysis. Preserve the source manifest and the exact samplesheet used for a pipeline run in an appropriately access-controlled location.
- nf-core samplesheet schemas differ across pipelines and may change between pipeline versions. Use the selected pipeline’s documentation and validation command as the final guide for required column names and values.
- Batch assignment is an analysis choice, not a substitute for modeling technical effects. Retain the original batch metadata and document how artificial batches were constructed.
- Resource recommendations are empirical starting points rather than guarantees of successful execution or optimal allocation.
