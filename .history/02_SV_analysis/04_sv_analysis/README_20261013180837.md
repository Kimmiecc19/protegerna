# Structural variant analysis in AnswerALS

This directory contains the structural-variant (SV) analysis workflow for the dissertation’s ALS cohort. 

It processes whole-genome sequencing callsets, consolidates calls from Manta and TIDDIT, annotates and prioritizes candidate events, evaluates call quality and carrier evidence, and prepares tables and figures for review and dissertation reporting.

The workflow is designed for research nomination and cohort analysis. Its outputs are not clinical diagnoses or clinical variant classifications.

## Workflow at a glance

```text
AnswerALS CRAM/CRAI + cohort metadata
              │
              ▼
Sarek (Manta + TIDDIT callsets)
              │
              ▼
OctopuSV correction, caller merge, cohort union/intersection
              │
              ▼
AnnotSV annotation (filtered candidate-gene and unfiltered modes)
              │
              ▼
SV QC, prioritization, participant tables, and manual evidence review
              │
              ▼
Audited research release, dashboard, and dissertation figures
```

## Directory guide

| Directory | Purpose |
| --- | --- |
| `01_sarek/` | Sarek samplesheet generation, run configuration, launch script, and resource analysis. |
| `02_octopusv/` | Manta/TIDDIT VCF correction and merging, cohort union/intersection callsets, and caller statistics/plots. |
| `03_annotsv/` | ALSoD gene/transcript mapping and filtered or unfiltered AnnotSV execution. |
| `04_sv_analysis/` | VCF QC and burden summaries, AnnotSV prioritization, participant-level tables, raw-record review, evidence summaries, and audited-release build/verification scripts. |
| `05_dashboard/` | Shiny application for exploring SV annotations and linking out to external genomic and literature resources. |
| `06_dissertation_figures/` | R scripts and style helpers for cohort statistics and dissertation workflow figures. |

Results directories and data files may contain large or access-controlled cohort outputs. The scripts and result snapshots are separate: commands below describe how to reproduce stages when the required source data and software are available.

## Main stages

### 1. Prepare samples and call SVs with Sarek

`01_sarek/01_create_samplesheet_batches_sarek.py` locates CRAM/CRAI files and writes split Sarek samplesheets. It currently sets `NUM_SPLITS = 14`; check the batch count, sample identifiers, and CRAM/CRAI pairing for the cohort before using the generated sheets.

`01_sarek/03_03_aals_sarek.sh`, `03_02_aals_sarek.json`, and `03_1_aals_sarek.config` provide a Sarek 3.5.1 launch/configuration example. The shell script contains placeholder machine paths and must be adapted for the execution environment, reference files, samplesheet, output directory, and scheduler profile. Sarek is run with Nextflow and Apptainer in the documented example. Resource analysis support is in `02_analyse_resources_sarek.py`.

### 2. Consolidate Manta and TIDDIT calls

`02_octopusv/01_octopusv_manta_tiddit.sh` accepts a Sarek results directory, corrects and combines caller outputs per participant, then builds cohort-level union and intersection callsets and reports. It checks VCF validity and tracks merge parameters to support safe reuse of existing outputs.

Example (run in a Bash environment with `bcftools` and `octopusv` available):

```bash
bash 02_octopusv/01_octopusv_manta_tiddit.sh \
  --input-dir /path/to/sarek/results \
  --out-dir /path/to/octopusv/results
```

The script defaults to SV lengths from 50 to 100,000 bp. Use `--help` for options such as `--dry-run`, `--force-merge`, and `--skip-merge`. Existing outputs without a parameter record require careful review before adoption. Cohort union/intersection are caller-consolidation sets; they are not independent biological truth sets.

### 3. Annotate and prioritize events

`03_annotsv/01_build_alsod_gene_map.py` retrieves the ALSoD gene list and looks up gene/transcript identifiers using Ensembl release 112 (GENCODE v46). A matching gene/transcript map is retained under `03_annotsv/data/` for prioritization.

`02_run_annotsv_filtered.sh` runs AnnotSV on the cohort intersection and union callsets. In `filtered` mode, it applies the supplied ALS candidate gene list; in `unfiltered` mode, candidate-gene filtering is disabled. `03_run_annotsv_unfiltered.sh` is the companion launcher. The runner’s default paths are specific to the original compute environment; provide paths through its options or environment variables (`INPUT_DIR`, `OUT_DIR`, `GENES`, `ANNOTATIONS`, and `ANNOTSV_BIN_DIR`). AnnotSV and its annotation resources must be installed separately.

`04_sv_analysis/02_annotsv_prioritization.py` selects and ranks candidate events, with separate intersection and union-only analyses. Union-only matching uses shared source IDs or exact chromosome/start/end/SV type, so it is a defined callset comparison rather than approximate allele normalization. The script generates complete event tables, selected priority tables, summaries, and manual-review shortlists.

### 4. Assess call quality and review evidence

`01_sv_qc_analysis.py` summarizes per-VCF SV quality and carrier burden without pooling overlapping caller/callset records. Its defaults include PASS records and 50–100,000 bp; breakends/translocations and unknown lengths are excluded from size-based analyses. Genotype interpretation is disabled by default and can be enabled with caller-reported genotype settings. Check the script’s `--help` for full options and output definitions.

The manual-review tools provide a staged evidence audit:

1. `04_01_sv_review_extract.py` matches shortlisted events to raw participant-level Manta/TIDDIT records and writes event, record-match, carrier-status, manifest, and header-definition tables.
2. `04_02_sv_review_evidence.py` converts caller fields into explicit split-read, paired-end, read-depth, and quality evidence and summarizes evidence by carrier and event.
3. `05_01_build_audited_release.py` reconciles a saved audit with annotation tables and writes release tables, participant support, integration pairs, and input checksums.
4. `05_02_verify_audited_release.py` checks release outputs and scientific edge cases against the saved audit inputs.

Absence of a matched call is not evidence of a reference genotype. Prioritization and audit labels are research review aids; they do not establish pathogenicity or clinical significance.

### 5. Explore results and prepare figures

`05_dashboard/proteGErna-SV.R` launches the Shiny SV viewer and resource search. It requires the R packages listed near the start of the app and a suitable annotated SV dataset. Keep participant-level data within its access-controlled environment.

`06_dissertation_figures/01_octopusv_stats_plots.R` and `02_sv_workflow_figures.R` create cohort and workflow figures. The latter reads OctopuSV outputs, prioritization summaries, and audited-release tables; some expected paths and cohort assumptions are defined in the script. `02_sv_thesis_style.R` supplies shared figure styling. Review the input paths and output location before running.

## Software and environment

The workflow spans several tools and runtimes; exact versions should be recorded for each run:

- Nextflow and the Sarek pipeline (the included example targets Sarek 3.5.1)
- Apptainer or another supported Sarek execution profile
- `bcftools` and OctopuSV
- AnnotSV and its annotation data
- Python 3
- R and packages required by the figure scripts and Shiny dashboard

## Data and reference resources

The workflow uses AnswerALS cohort data, the [ALSoD ALS gene database](https://alsod.ac.uk/), [Ensembl](https://www.ensembl.org/), and AnnotSV annotation resources. Cite the source data, software, and resource versions used in any resulting publication or dissertation chapter.
